# 新来源接入指南

## 结论

未来仍然采用“一个作者或资料来源一个原始文件夹”，但不再为每个人固定创建一套全新代码。系统分成两层：

1. 通用格式适配器：处理常规 MD、TXT、PDF、DOCX、JPG、PNG。
2. 来源专用适配器：处理连麦说话人、时间戳、截图顺序、Word 图文关系、特殊日期或重复内容等语义结构。

作者不是一个必须复制的“角色程序”。作者身份保存在每个检索块的 `source_id`、作者、日期和定位字段中；教学、跨来源比较、事实核验、交易日志复盘仍由现有五个功能角色完成。这样新增十个作者也不需要新增十个角色。

## 什么时候可用通用适配器

满足以下条件时使用 `generic_mixed`：

- 一个文件基本对应一篇文章或一个文档；
- MD/TXT 可直接读取；
- PDF 只需要页码和正文，低文本页可直接 OCR；
- DOCX 主要价值在正文和表格；
- 图片之间没有必须人工理解的连续关系。

出现以下任一情况时改用专用适配器：

- 多人聊天或直播稿需要保留说话人和时间戳；
- 多张截图合起来才是一篇文章，且文件名无法可靠恢复顺序；
- Word 正文与内嵌图互相解释，漏掉图片会改变结论；
- PDF 页面是复杂图表、盘口或数字密集型截图；
- 同一来源有特殊章节、课程期数或观点演化关系；
- 通用导入质量报告出现未支持格式或大量低置信度内容。

## 标准操作

先把新文件夹放在知识库根目录，例如：

`C:\Users\20577\Documents\炒股\知识库\新博主资料`

然后在该项目中运行：

```powershell
$kbPython = "C:\Users\20577\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"

# 只检查，不修改配置
& $kbPython _知识库系统/scripts/register_source.py "新博主资料" --id new_blogger --name "新博主" --dry-run

# 正式登记
& $kbPython _知识库系统/scripts/register_source.py "新博主资料" --id new_blogger --name "新博主"

# 导入、建索引、生成跨来源覆盖地图并验证
& $kbPython _知识库系统/scripts/import_source.py --source new_blogger
```

如果预检查显示结构复杂，使用 `--adapter specialized` 登记。系统会停止通用导入并要求先建立专用适配器，不会为了“看起来成功”而静默丢失内容。

## 新对话如何使用

从知识库根目录新建 Codex 任务即可。新任务先读取根 `AGENTS.md` 和 `sources.yaml`，随后可以按来源检索：

```powershell
python _知识库系统/scripts/query_kb.py "问题关键词" --source new_blogger --limit 8 --show-parent
```

跨来源问题必须分别检索每个来源，再比较概念、前提、分歧和失效条件；主题覆盖数量只代表材料数量，不代表作者观点一致。
