# 多来源交易知识库使用说明

## 在 Codex 中使用

把 `C:\Users\20577\Documents\炒股\知识库` 设为本地项目的主文件夹。从该项目中新建对话，新对话即可读取同一套知识库文件和项目规则，但聊天记录彼此独立。

常用提问方式：

- `只根据复利杯，解释闻少如何判断情绪周期，并给页码和时间戳。`
- `比较南京路彼岸和郁金香花园对弱转强的定义、前提和分歧。`
- `这个历史方法在当前市场是否还成立？把历史观点和最新公开证据分开。`
- `根据我的交易日志复盘本周模式外交易，不要给荐股。`
- `先分别检索三个来源，再比较他们对“竞价强弱”的定义、前提、分歧和失效条件。`

## 命令行检索

```powershell
python _知识库系统/scripts/query_kb.py "情绪周期 拐点" --source fulibei --limit 8
python _知识库系统/scripts/query_kb.py "仓位 回撤" --author 猴年古月 --limit 10
python _知识库系统/scripts/query_kb.py "转点 卡位" --source nanjinglu_bian --limit 8
python _知识库系统/scripts/query_kb.py "筹码 竞价" --source tulip_garden --limit 8
```

来源标识：

- `fulibei`：复利杯连麦文字稿
- `nanjinglu_bian`：南京路彼岸文章
- `tulip_garden`：郁金香花园 Word 课程与截图文章

查询命中后，Codex 应继续读取 `parent_text` 或对应标准化文本，不要只根据 420 字预览直接下结论。OCR 块的关键数字、盘口和图表必须回看原 PDF/图片。

## 更新知识库

```powershell
python _知识库系统/scripts/build_manifest.py
python _知识库系统/scripts/build_index.py
python _知识库系统/scripts/build_cross_source.py
python _知识库系统/scripts/validate_kb.py
```

若新增的是 PDF、Word 或图片资料，先运行相应导入器。它们需要 Codex 自带的文档 Python：

```powershell
$kbPython = "C:\Users\20577\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $kbPython _知识库系统/scripts/import_nanjinglu.py
& $kbPython _知识库系统/scripts/import_tulip_garden.py
```

导入器使用哈希与 OCR 缓存；未变化的页面和图片不会重复识别。

原始资料目录始终只读。所有派生文本、索引和报告写入 `_知识库系统`。

## 以后新增其他作者

继续采用“一个来源一个原始文件夹”。常规 MD/PDF/DOCX/图片先使用通用接入器：

```powershell
$kbPython = "C:\Users\20577\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $kbPython _知识库系统/scripts/register_source.py "新来源文件夹" --id source_id --name "显示名称" --dry-run
& $kbPython _知识库系统/scripts/register_source.py "新来源文件夹" --id source_id --name "显示名称"
& $kbPython _知识库系统/scripts/import_source.py --source source_id
```

详细的通用/专用适配器判断见 `_知识库系统/新来源接入指南.md`。
