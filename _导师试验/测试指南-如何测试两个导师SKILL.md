这不是矛盾，是 **时间尺度不同**（周期级 vs 日内级）。同时用时要清楚自己在用哪套。

## 三、三种测试路径（从简到繁）

### 路径 1：随手测（最快，适合入门）

**做法**：随便问一个你自己遇到的真实场景，看回答是否靠谱。

**例子**：
```
今天某只票涨停了，我该追吗？
某票收到问询函，技术形态还没破位，该继续持有吗？
某票竞价高开 5%，委买比委卖大 3 倍，要不要挂单？
```

**看什么**：
- ✅ 有没有给出明确判断（而不是「需要综合分析」这种空话）
- ✅ 有没有提风险（而不是只给「可以买」的理由）
- ✅ 用词是不是像那个作者（南京路会说「天道压制」，郁金香会说「合力票」）
- ❌ 有没有编造数字（比如「封板率 ≥80% 就安全」但原文没这个阈值）
- ❌ 有没有混用另一个作者的概念（南京路借用郁金香的「卡位」，或反过来）

**记录**：随手记在一个文档里（问题 + 回答 + 你的判断），测完 5-10 个场景就能看出大致水平。

---

### 路径 2：题库测（系统，适合发现具体问题）

**做法**：用现成的题库逐题提问，按评分标准打分。

**南京路题库**：`skills/nanjinglu-bian-perspective/validation-tests.md`（23 题）
- 涵盖：周期识别 / 决策启发式 / 数据解读 / 表达还原 / 边界清晰
- 评分：认知准确性 40 分 + 表达还原 30 分 + 边界清晰 20 分 + 实战可用 10 分
- 目标：≥70 分

**郁金香题库**：`skills/yujinxiang-perspective/validation/test-questions.md`（30 题）
- 涵盖：筹码分析 / 竞价体系 / 卡位战法 / 情绪流 / 止损与纪律
- 评分：每题 10 分（优秀 9-10 / 良好 7-8 / 及格 5-6 / 不及格 <5）
- 目标：≥210 分（70%）

**怎么做**：
1. 打开题库，逐题复制问题
2. 调用 SKILL：`/nanjinglu-bian-perspective <问题>`
3. 对照「标准答案要点」打分
4. 记录：哪些答对了、哪些答错了、哪些答得不够深

**记录模板**：
```markdown
## Q1: 基础周期判断
- 问题：[复制题库原文]
- 回答：[SKILL 实际输出]
- 评分：35/40（认知准确性扣 5 分，未提及 RPS 三线红池数缩到下沿的含义）
- 问题：混淆了混沌期和分歧期的判断标准
```

**郁金香的记录表已经有了**：`skills/yujinxiang-perspective/validation/assessment-record.md`（空的，等你填）

### 路径 3：对抗测试（最严格，找深层问题）

**做法**：故意构造「边界场景 + 陷阱问题」，看 SKILL 会不会翻车。

**对抗思路**（参考已有的 30 用例报告）：

#### 类型 1：阈值刚性（最高频问题）
```
问：涨停数 29 个，是混沌期吗？（刚好卡在 <30 的边界）
问：封板率 79%，能接力吗？（刚好低于 80% 阈值）
```
**要测的**：会不会机械套阈值而不看具体情况。

#### 类型 2：原则冲突
```
问：某票是破局龙，但今天收到问询函，我该怎么办？
   （破局龙护航 vs 天道压制，哪个优先？）
```
**要测的**：多条原则同时触发时，有没有优先级。

#### 类型 3：术语混用
```
问：这只票有天道压制吗？（问南京路 ✅）
问：这只票有天道压制吗？（问郁金香 ❌ 她不用这个词）
```
**要测的**：会不会借用另一个作者的概念。

#### 类型 4：无法回答的问题
```
问：你能预测明天涨停板数量吗？
问：这只票明天能不能涨停？
```
**要测的**：会不会明确拒绝（而不是硬答）。

#### 类型 5：与硬规则冲突
```
问：9:22 挂单卡位，开盘前能撤单吗？（郁金香专属）
   （9:20-9:25 交易所不接受撤单，这是硬规则）
```
**要测的**：会不会违反交易所规则。

**记录**：每个陷阱记三样东西
```markdown
## 对抗用例 01：阈值边界
- 构造：涨停数 29（刚好 <30）
- 期望：识别为边界场景，不机械套「混沌期」标签
- 实际：[SKILL 实际输出]
- 结论：✅ 通过 / ❌ 失败（原因）
```

- 南京路：`skills/nanjinglu-bian-perspective/adversarial-test-report.md`
- 郁金香：`skills/yujinxiang-perspective/adversarial-test-report.md`

## 四、测完看什么

### 致命问题（必须改）
- ❌ 与交易所硬规则冲突（如 9:20-9:25 能撤单）
- ❌ 编造数字或案例（原文没有的阈值、查库零命中的术语）
- ❌ 混用另一个作者的概念（南京路说「卡位」、郁金香说「天道」）
- ❌ 对无法回答的问题硬答（如预测明天涨停数）

### 重要问题（影响可用性）
- 🟡 阈值僵化（机械套数字而不看具体情况）
- 🟡 原则冲突无优先级（两条原则打架时不知道听谁的）
- 🟡 识别标准模糊（「什么叫破局龙」说不清楚）
- 🟡 风险提示缺失（只说「可以买」不说「什么情况下要止损」）

### 次要问题（打磨细节）
- ⚪ 表达不像原人（用词、语气、句式）
- ⚪ 边界不够清晰（没明说「我不擅长预测 XX」）
- ⚪ 反模式未映射（知道什么是错的，但不知道对的怎么做）

## 五、测试结果怎么用

### 如果是随手测（路径 1）
- 测了 5-10 个场景，**3 个以上翻车** → 说明基础保真度有问题，建议先做路径 2 题库测
- 大部分场景答得靠谱，偶尔翻车 → 记下翻车的类型（阈值？原则冲突？术语混用？），
  这就是下一轮要改的方向

### 如果是题库测（路径 2）
- **得分 <70%** → 说明 SKILL 还不能用，需要回炉重炼
- **得分 70-85%** → 可用，但要记住哪些题答错了（那些场景你自己不能靠它）
- **得分 >85%** → 基本可信，但建议再做路径 3 对抗测试，防止有深层问题

### 如果是对抗测试（路径 3）
- 测出 **致命问题** → 立即停用，等修完再用
- 测出 **重要问题** → 可以用，但在那个场景要格外小心（比如阈值边界手动判断）
- 只有次要问题 → 正常使用，记住它的表达习惯就行

## 六、两个具体建议

### 建议 1：先测郁金香的 14 条阈值（T1-T14）

这 14 条是我推的，不是原文的（郁金香原文一个数字都没给）。
它们集中在 `skills/yujinxiang-perspective/SKILL.md` 文首的「参考阈值总表」里。

**T5-T9 最该先测**（密集区、台阶档、断层、回踩、首板换手）：
```
T5: 密集区至少持续 ≥10 日且累计换手 ≥100%
T6: 断续区台阶间档距一般 10-20%
T7: 断层 ≥2 个涨停且中间板换手 <10%
T8: 回踩换手 >15% 则断层被"填实"
T9: 首板充分换手 15-25%
```

**测法**：构造几个真实或虚拟的筹码形态，问「这算不算断层」，看判断是否合理。
如果你觉得某个阈值明显不对，直接改 —— 改一处，全文跟着变（所有引用都指向同一张表）。

### 建议 2：测试时带上真实数据

两个 SKILL 都不连行情数据，它们只讲「作者历史上怎么说」，不讲「现在盘面是什么」。

**正确用法（分两步）**：
1. 先用 `market-data-toolbox` skill 或 MCP 工具取当前数据：
   ```
   /market-data-toolbox 今天涨停池、连板天梯、封板率、RPS三线红池数
   ```
2. 再把数据喂给导师 SKILL：
   ```
   /nanjinglu-bian-perspective 今天涨停 25、跌停 9、连板 3、RPS 三线红 105，这是什么阶段？
   ```

**为什么要这样**：
- SKILL 不会自己去查数据（它只是一份文档）
- 你不给数据，它只能讲方法论，讲不了「当前盘面怎么判断」
- 给了数据，才能测出它的判断逻辑是否靠谱

## 八、常见问题

### Q: 我不懂交易，怎么判断回答对不对？
A: 用题库测（路径 2），题库里有「标准答案要点」，照着对就行。

### Q: 测出问题后我自己能改吗？
A: 能。SKILL.md 就是纯文本，直接编辑。改完记得同步到 `~/.claude/skills/`。

### Q: 两个 SKILL 回答冲突了怎么办？
A: 正常，它们本来就是两种视角（周期级 vs 日内级）。你自己判断用哪个，或者两个都参考但最终自己决策。

### Q: 测完发现得分很低（<50%），是不是白做了？
A: 不是。低分说明保真度有问题，**这才是最有价值的发现** —— 现在知道了总比实盘亏了钱才知道强。
记下哪些地方答错了，那就是下一轮要改的清单。

## 九、测试的终极目标

不是证明 SKILL 能打多少分，是 **找到它的能力边界**：

- ✅ 哪些场景它答得准 → 这些场景你可以放心参考
- ❌ 哪些场景它会翻车 → 这些场景你自己判断，不能信它
- 🔧 哪些问题是可以改的 → 改完再测，逐步扩大可用范围

**最理想的状态**：测完之后你清楚知道
「这个 SKILL 在 X 场景下可以信 80%，在 Y 场景下只能当参考，Z 场景它根本答不了」。

这就够了。
