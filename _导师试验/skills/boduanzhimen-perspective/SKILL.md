# 波段之门视角 (Boduanzhimen Perspective)

## 先纠一个常见误解：这不是波浪理论体系

用户可能因为看他常说"三浪三""C浪"而以为这是艾略特波浪理论的库。**不是。**

语料实测词频，**口径是 723 篇原始 md 全文（含留言区）里出现该词的篇数**，
不是入库块数 —— 两者差很多（"底部"按正文块口径只有 213 篇）。
2026-08-09 用原始 md 重新核对过，9 个词逐个吻合：

| 词 | 出现篇数 |
|---|---:|
| 底部 | 286 |
| 顶部 | 205 |
| 周期 | 201 |
| 结构 | 180 |
| 分时 | 129 |
| 均线 | 110 |
| 波浪 | 47 |
| 艾略特 | 8 |
| 推动浪 | 0 |

他的主干是**时间周期 + 自拟指标 + 多周期结构**，浪型只是顺手借用的描述词。
他本人对纯结构派明确不屑，原话（`[2025-05-20]今年有没有三浪三`）：

> 除了李彪，我没见一个用缠论说对大行情时间的，没有时间的推论，等于没说。
> （同篇留言区第 6 条作者回复）
> 有时间，不知道具体空间，是绝对能够赚钱的。有空间，没时间，这绝对是忽悠人的。
> （注意：这是**同篇第 7 条**另一条回复——上面两条常被合并引用，其实是两条）

另外两个防串味提示：①他是「背驰」的公开否定者（"我从来不看有没有背驰"
`[2024-02-18]假期杂记3`），检索器词频表把他列为特色词是反的；
②检索结果里的 `主题:` 标签是机器打的（taxonomy），**不等于他的用语**——
「情绪周期」原词在他 0 块，别被标签带进阶段论框架作答。

**所以：用户问"用波浪理论分析一下"时，先说清这一点，再按他真正的方法回答。**
把他包装成波浪理论专家是曲解，会让用户拿错工具。

## 回答工作流（先查库，再回答）

**核心原则：不凭本文档回答。收到问题先去语料库查他自己怎么说，再用他的视角组织答案。**

### Step 1：判断要不要查库

| 问题类型 | 动作 |
|---|---|
| 需要他的具体观点、某概念怎么理解、某情况怎么判断 | **必须查库**（Step 2） |
| 他的指标怎么算 | 查库 + 读 `boduanzhimen_indicators.py`（15 个已实现，可直接跑） |
| 当前盘面事实（今天涨停几家、某票现价） | 走 `live-market` MCP，**不是**本 SKILL 的职责 |
| 他的预测准不准 | 跑 `boduanzhimen_backtest.py`，**不要凭印象说**（见下方回测节） |

### Step 2：查库（这一步不可跳过）

```bash
cd "C:\Users\20577\Documents\炒股\知识库"
# 注意 --no-expand：全局同义词表是短线情绪体系建的，对他家是噪声源（2026-08-24 起
# query_kb 默认开扩展，查本源必须显式关掉）
python _知识库系统/scripts/query_kb.py "<关键词>" --source boduanzhimen --limit 6 --no-expand
```

**用哪个 python**：全部用系统 Python312
`C:\Users\20577\AppData\Local\Programs\Python\Python312\python.exe`
（yaml/numpy/pandas/pypdf 全有，225 项测试在它上面跑）。codex 运行时 08-07 被重置
后只剩标准库，别再用它。

**引用 paid_article 块前必须先核对 document_id 是否在文末「存疑名单」里**——
付费包混有他人文章，光靠文末警告不够，这一步是流程硬要求。

**这个库的特殊之处：作者留言回复占了 4984 块，是正文块（1909）的 2.6 倍。**
正文里他经常说"看下面这张图"把话留在图里，而留言区回答读者时反而把话说透了。
所以查到 `chunk_type=author_reply` 的块不要当次要材料——那常常是最直接的答案。

块类型（共 **8029 块**，2026-08-25 实测。OCR 引擎 08-24 从 Windows OCR 切换为
RapidOCR/dual 后块数微降、文字更干净。登记 849 份文档，其中 4 份是内容完全相同的
重复抓取，只登记不建块）：

| chunk_type | 数量 | 是什么 |
|---|---:|---|
| `author_reply` | 4984 | 留言区他本人回复，见下面三种形态 |
| `article_body` | 1909 | 公众号正文（723 篇，2023-02~2026-07） |
| `paid_article` | 531 | 付费文章（2012-2025，101 个 PDF，其中 65 个扫描版走 OCR） |
| `chart_ocr` | 586 | K线图内文字（**数字可能有识别错误**） |
| `indicator_formula` | 19 | 通达信指标源码 |

`author_reply` 有三种形态，**看开头前缀就能分清他在回答谁**：

| 前缀 | 条数 | 含义 |
|---|---:|---|
| `读者问：…／作者答：…` | 4337 | 紧跟某条读者留言，是真的在回答那个人 |
| `作者续言（承接本篇第N条，同一串第M条）：…` | 641 | 他连发的第 2 条起，**不是**在回答上面那条留言 |
| `作者留言：…` | 6 | 留言区以他自己开头，前面没有读者留言 |

那 641 条续言原先被错标成在回答同一条读者留言（审查报告 P1-6，实测 12.8% 出错、
涉及 243 篇，最严重一篇一条留言被 12 条回复共用）。他在留言区经常连发多条
独立发言，比如「借楼一用」之后连续汇报自己的仓位动作。
**引用续言时不要把上面那条读者提问当成它的语境** —— 要还原上下文就按
`承接本篇第N条` 去查同篇那一条。

命中块读起来像被截断时，加 `--show-parent` 读完整父块。

**查完没结果就说没结果。** 正确说法：「这个问题我在他的语料里没找到直接论述，
以下是基于他其他观点的推断，不是他说过的话」。

### Step 3：用他的视角回答

1. **先给结论**，一句话说清（他自己的风格就是先给判断）
2. **再给依据**，引刚查到的原话
3. **标出处**，格式 `[波段之门｜文章名｜日期｜locator]`
4. **该说不知道就说不知道** —— 他本人极常说"不知道"（"这次反弹会到哪里？不知道！"）

## 正文里的 〔图〕 是什么

导入时把图片位置标成了 `〔图〕`。看到它意味着：**该处原文是一张图。**

这批语料的固有性质：平均每篇 7.4 张图（其中 K 线等实质图 5.2 张，
共 5283 张 / 715 篇），他大量判断（"上面那条均线是70""看到黄线了吗"）
指向图内信息。

**图内文字已 OCR。** 下表是旧引擎（Windows OCR）时代的分桶，各项相加正好 3718；
2026-08-24 引擎切 RapidOCR 后入库 **586 块**（汉字量与旧版持平、拆字坏块率归零），
其余分桶未重新统计，以缓存为准：

| 结果（旧引擎口径） | 张数 | 说明 |
|---|---:|---|
| 入库（`chunk_type=chart_ocr`） | ~~628~~ 现 586 | 他写在图上的判断 |
| 中文占比过低 | 1196 | 数字刻度、板块代码 |
| 识别为空 | 913 | 纯 K 线图，无文字 |
| 文字太短 | 725 | 只有水印或零星数字 |
| 行情面板 | 249 | "A股成交B股成交国债成交…"字段名连排，中文比高但无语义 |
| 纯水印 | 7 | 去掉"公众号·波段之门"后没剩下内容 |

入库的那批有实质价值，例如图里写着"3949 已破, **3936 是第二道防线**,这个再破,
后面就有点深了"、"震荡区间大约在 4167 到 4055 点之间"。
⚠️ 对抗测试实测纠错：前一句原文是「**第二道**防线」不是第一道——SKILL v1.0 曾写错；
且这类句子留言区文本层也有同文（如 boduanzhimen-wx-20664d4afc28 留言区作者回复），
**举「图内独有」的例子前必须先查证正文/留言区是否同日有表述**，
不要拿可被一行查询推翻的断言论证图内文字的价值。

门槛的判据是**有没有句读**，不是单纯的字数：他写在图上的话是完整句子（标点 2~7 个），
行情面板和商品标签标点 0 个。所以放宽字数时同时要求 ≥2 个标点，两者一起卡
（审查报告 P1-7 + P2-1：原来纯按 40 字截断，既误杀短判断又漏进面板噪声。
修完新收进 96 块真实判断，同时把 249 张面板挡在外面）。
测试在 `test_import_boduanzhimen.py`（14 项）+ `test_mutation_import_boduanzhimen.py`（11 个变异）。

**但 OCR 有错字**（"判断底部"识别成"判底部"、"算及格"成"篡及格"），
引用 `chart_ocr` 块时要注意：**数字可能被误认**（`4034` vs `4D34`），
关键点位必须回看原图确认，不要直接把 OCR 出的数字当他的原话报给用户。

仍读不出的部分（画在图上的线、颜色、位置关系）：
- 图片清单在 `_知识库系统/source_libraries/boduanzhimen/maps/image_map.jsonl`
- 按 `document_id` 找该文的图，`kind=chart` 是K线图（已排除 1565 张头像/UI）
- **图片扩展名不可信**：4214 张 PNG 存成 `.jpg`，`real_format` 记录了按文件头判定的真实格式
- OCR 原始结果（含被丢弃的）在 `image_ocr_cache/*.json`，带 `kept` 和 `drop_reason`
- 诚实做法是告诉用户"这一段的关键信息在原图里"，而不是猜图里画了什么

## 核心心智模型

以下框架用来**组织答案结构**，具体论述仍要现查语料，不要拿这里的概括当他的原话。

### 模型1：时间优先于空间

他判断行情的顺序是先定时间、再谈空间，反过来在他看来就是忽悠。

- "有时间，不知道具体空间，是绝对能够赚钱的。有空间，没时间，这绝对是忽悠人的。"
- 具体手法：数周期（`[2023-03-01]` 说"每隔20个季度就有一个比较大的转折"）、
  11 序列（从某个转折日起循环编号 1-11，落在特定编号上容易变盘）
- 他会给出明确的**变盘日**："日线的变盘日分别在3月2日，下下周初，3月底附近"

### 模型2：多周期从大到小嵌套

季线 → 月线 → 周线 → 日线 → 分时，逐级收敛。语料覆盖（**正文块口径**，
即 1909 块 `article_body` 里的命中数）：日线 240、周线 163、月线 70、季线 10、分时 92。
若按全部 8082 块算则是 431 / 288 / 139 / 18 / 142 —— 引用数字时必须说明是哪个口径。

- 买股票的顺序他说得很直白："先看大盘，再看板块，再看个股"（`[2026-02-13]`）
- 大周期定方向，小周期定入场点。周线不乐观时日线反弹他不参与
- "我只做周线级别的行情，但这不妨碍我对短线的分析"（`[2024-06-17]`）

### 模型3：相对强度（他最核心的自拟工具）

`A := (C / INDEXC) * 10000`，即个股价格 ÷ 同期大盘指数。**两组参数别混**：

- **强度线**（看状态）：比值的 13/34/55/89 均线排列
- **选股公式**（震荡市选股文）：另一组 13/21/34/89 + `M13/M1>1.15` +
  `HHV(H,104)/LLV(L,104)>2`（104 日区间翻倍）+ 上市超 400 根

含义：个股自己涨不算强，**跑赢大盘才算**。这条比值线上穿意味着资金在从
大盘搬到这只票。⚠️ 「图上标的 1/2/3/4 就是各级别均线上穿的转折点」这句 v1.0
的断言无法核验（对抗测试 Q11），降级为「图上有数字标记、含义需看原图」。
可核验的状态门槛是：**前三条均线站上 M34（蓝线）才可交易**（`[2023-02-01]`）。

这个公式在 4 个通达信指标源码文件里出现（`chunk_type=indicator_formula` 口径；
若按全部块算，`INDEXC` 命中 16 块、涉及 11 篇文档，其中付费文章 11 块），
是他选股文章的共同底座。已实现为
`boduanzhimen_indicators.strength_lines(frame, index_close)` —— 注意第一个参数是
**DataFrame**（列 open/high/low/close/volume），不是收盘价 Series。

### 模型4：仓位话语分两层——给读者的纪律建议 ≠ 本人行为实录

⚠️ v1.0 曾把「我从不满仓」写成他的行为硬约束。对抗测试 Q25 用语料推翻了它：
`[2023-10-23]` 他自报大跌加仓至 **99.96%**；`[2025-01-08]` 自认技术上可以满仓、
但刻意不这么做给人看；`[2024-09-05]`/`[2024-02-17]` 牛市自述「最多八成」。
正确用法：

**第一层·对读者的纪律建议**（可引用、可转述，这是他反复强调的话语）：
- **总仓位不超过 7 成**："我一直强调不要超过7成仓位"（`[2026-03-16]`）
- **不要满仓**：读者说自己满仓，他直接回"请不要满仓,我从不满仓"（`[2026-02-07]`）
  ——注意这是纪律表达
- **单票不超过 2 成**："一只票最多两成仓，总仓位最高7成仓"（`[2025-01-02]`）
- 时间轴：「7成+单票2成」是 2025-2026 的稳定话语；2023-2024 有实质差异
  （自称「极少满仓」而非从不、牛市说到八成）

**第二层·本人行为实录**（回答「他自己怎么做的」时必须如实呈现，别拿第一层冒充）：
- `[2023-10-23]` 大跌中加仓至 99.96%
- `[2024-09-26]` "先把仓位占上，再慢慢调仓换股"

被问「他自己满过仓吗」时，答案是有实录；被问「他建议满仓吗」时，答案是明确反对。
两句话不能混。

**翻译时的坑（已在代码里处理并有测试守着，引用时别改回去）**：

- 通达信 `SMA(X,N,M)` 是递推加权 `Y=(M*X+(N-M)*Y')/N`，等价于 `ewm(alpha=M/N, adjust=False)`。
  写成 `ewm(span=N)` 是错的（span=3 的 alpha 是 0.5，而 M/N 是 1/3）。
- 通达信 `STD` 是**样本**标准差 `ddof=1`（已实测，pandas 默认值正好对）。
- `INDEXC`（大盘收盘价）在通达信里自动对齐，Python 里必须显式传入，
  索引不重叠时 `strength_lines` 会直接抛错而不是静默返回 NaN。
